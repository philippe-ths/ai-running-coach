# Coach output is a prose message with a thin structured tail; the structured report is demoted

Today the coach's product is a structured JSON `CoachReport` (headline, thesis, claims, takeaways, next_steps) generated under "output ONLY valid JSON" and rendered field-by-field. That shape made every claim machine-traceable, but it is the named cause of the owner's core complaint: the reports read samey, form-shaped, and inhuman, and forcing structure before (and during) generation degrades the reasoning itself, the failure the owner's research flagged. The north-star (decision 4) reframes the output as a human message within a `Coaching relationship`.

We invert the generation order and demote the structured report. **One Anthropic call with adaptive thinking produces, in token order: private reasoning, then the coach's prose `message` (markdown, unconstrained, the product the runner sees everywhere), then exactly one strict-schema tool call carrying a thin bookkeeping tail: `headline`, 0-3 machine-readable `next_steps` (same `action`/`details`/`why` shape the learning loop already consumes), `risks` flag declarations, and `questions` with typed tappable options. Structure carries affordances and memory hooks, never content: the tail may contain nothing the message did not say.** Storage stays in the existing `coach_reports.report` JSON column under a new cache identity (`coach_message_v1`, schema 2.0); zero migrations; cutover and rollback are each a pure `COACH_PROMPT_ID` config flip. The deterministic policy validator's six rules police the full prose plus every tail text field (its surface strictly grows), with one strengthening: a medical-overreach violation surviving the policy retry now forces a fallback instead of storing with a flag, because prose renders verbatim. The call is built to the strictest model parameter surface (no sampling params, adaptive thinking) so the Sonnet/Opus choice stays a config decision; A3 ships on `claude-sonnet-4-6`.

## Considered options

- **Keep the structured report and render it as prose client-side.** Rejected: structure-first generation is the exact failure this decision exists to kill; the output would stay form-shaped at the source.
- **Structured output with the message as a JSON string field.** Rejected: runs the product through constrained decoding and cannot guarantee prose-before-structure token order.
- **Two calls (write prose, then extract the record).** Rejected: doubles cost and latency, and an extraction call lets the machine record drift from what the author meant, corrupting the learning loop.
- **A claims array in the tail (per-claim evidence, the Dual-Track candidate).** Rejected: rebuilds the analytical report inside the tail, doubles the content, enlarges the prose/tail divergence surface, and pressures the model back toward enumerable-claim prose. Per-claim traceability of the rendered surface is deliberately traded for humanity; evidence refs survive on `next_steps`.
- **A new `exchanges` table now (the Message-First candidate).** Rejected for A3: it orphans the shipped A2 retrieval seam, forces permanent two-table union adapters, and pre-empts A1's event-unit data model. The Exchange record is deferred to A1; A3 accepts that storage may be re-homed then.
- **Full message/tail atomicity (discard the message if the tail fails).** Rejected: the message is the product; a bookkeeping failure becomes a visible degraded-tail state in which the runner keeps the coaching and the loop abstains (the existing M7 discipline). Atomicity is kept in one direction only: a tail is never stored without its message, so adherence never judges advice the runner never saw.

### How the chosen shape was selected

The decision came out of a three-candidate design panel scored by three independent judges (loop-and-safety, migration-and-ops, vision-fidelity lenses), who all reached the same ranking. The chosen In-Place Reframe scored 26/30 with zero fatal flaws; the two runners-up each carried a fatal flaw per judge and scored 15-15.5.

- **Dual-Track (a 1-6 ranked, evidence-backed `claims` array in the tail).** Eliminated primarily for its tail: a mandatory claims array rebuilds the structured analytical report inside the tail, keeping report-as-protagonist DNA and pressuring the model back toward form-shaped prose, the exact failure this decision exists to kill. It also took full atomicity (discarding good prose over bookkeeping), and its rollback was broken as drafted: a single `SCHEMA_VERSION` constant swap orphans every cached legacy row on rollback. Its salvageable parts (same-column storage, byte-equivalent legacy validator) were already in the winner.
- **Message-First (a new `exchanges` table).** Eliminated on cost and staleness, not vision (it had the best protagonist fidelity and A4/I1 setup). The new table orphans the shipped A2 retrieval seam (`fetch_prior_digests`/`fetch_prior_commitments`/`fetch_recent_user_digests` all read `coach_reports`, so A2c consolidation would silently freeze on legacy digests), forces permanent two-table union adapters, has the largest blast radius of the three, and its runtime-generated strict schema was invalid as written.
- **The fatal flaw both runners-up shared:** drafted against a stale snapshot (prompt v8, five validator rules, seven eval assertions, pre-A2d adherence gather), each omitted validator rule 6 (narrative-as-evidence, the A2c authority boundary) from its new validation entry point, so as submitted each would have weakened the gate. Repairable, but the winner was the only candidate whose integration claims verified true against the shipped code.

Two contributions from the runners-up were grafted into the winner: the typed `TappableOption` (`kind: rpe|pain|reply|dispute|custom`, payload) from Message-First, which freezes the real I1 quick-capture contract at near-zero cost, and order-agnostic tail parsing with `stop_reason` discipline (branch on `end_turn`/`max_tokens`/`refusal`) from Message-First plus the API fact-check.

### API parameter constraints (from the fact-check)

The call must be built to the strictest model parameter surface so the Sonnet/Opus choice stays a pure `COACH_MODEL_ID` config flip:

- Send no `temperature`/`top_p`/`top_k`: sampling parameters 400 on Opus 4.8 and omitting them is valid everywhere. `thinking={"type":"adaptive"}` is the supported mode on both Sonnet 4.6 and Opus 4.8. Nothing in the design is Opus-gated.
- `tool_choice: auto` is mandatory, not a preference. A forced tool choice both suppresses the preceding prose and is an outright API error under extended thinking, so auto + a prompt mandate + one corrective retry is the only viable mechanism, which makes the skip-the-tail failure mode inherent and the degraded-tail path required rather than optional.
- `max_tokens` must be generous (8-16K): thinking tokens count inside `max_tokens`, so a tight ceiling truncates the tail first (it generates last), directly inflating the design's own `tail_degraded` health metric. Log `stop_reason` and `usage`.
- The strict-schema subset forbids string `maxLength`, so the headline's <=80-char bound lives in the prompt, not the schema; the tool JSON is hand-frozen (not runtime Pydantic generation) to keep the prompt-cache prefix byte-stable.

## Consequences

- The learning loop survives by construction, not adapter: the tail's `next_steps` land at the same JSON key and shape `retrieval.fetch_prior_commitments` reads, so M7/M8/M10 and the LLM-free write-back run verbatim; `digest.py` gains one branch.
- The validator is refactored into shared rule bodies feeding a byte-equivalent legacy entry point (cached v1-v10 rows score identically) and the new prose entry point. Documented residual: rule 6's machine-checkable surface narrows to tail evidence paths; prose narrative-leakage is governed by prompt rule 24 and eval review.
- Prose/tail divergence (a commitment phrased only in prose exits the loop) is the accepted, deterministically-uncheckable blind spot, bounded by the mirroring prompt rule, the thin tail, and M7's conservative abstention; the #164 LLM-judge is the future mitigation.
- The M5 eval gate never goes dark: extractors learn the new shape, selftest gates both shapes, the refactor is proven no-op against live v10 rows, and the cutover is gated by a scorecard comparison on seeded regenerated data with re-baselined lexical thresholds.
- `coach_report_v1`..`v10` stay byte-stable; all cached history is retained under the versioned cache; old activities render forever via the legacy panel.
- The frontend renders a markdown message with tappable option chips; Telegram/email render the prose. Typed `TappableOption` (`kind: rpe|pain|reply|dispute|custom`, payload) freezes the I1 contract; delivery surfaces (inline keyboards, two-stage cadence) remain I1/A4 scope.
- Future reviews should not re-suggest re-structuring the product or full atomicity: prose-as-product, the thin tail, and degrade-not-withhold are the design, not accidents.

Three forks were put to the owner alongside the design and resolved here: (1) **medical floor hardening** — promote a `medical_overreach` violation that survives the policy retry from store-with-flag to forced fallback, since prose now renders verbatim (adopted, stricter never looser); (2) **Exchange record now or at A1** — defer the dedicated `exchanges` table to A1 where the north-star puts the event-unit data model, keeping the demoted `CoachReport` row for A3 and accepting a possible re-homing then; (3) **model choice** — ship A3 on `claude-sonnet-4-6`, evaluate the prose, and treat flat prose as a model question (not an architecture failure) before paying Opus prices.
