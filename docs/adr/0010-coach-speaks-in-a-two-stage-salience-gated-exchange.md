# The coach speaks in a two-stage Exchange gated by salience

A3 made the coach's output a human prose message, but it still fired exactly once per activity as a single heavyweight report, regardless of whether the run warranted depth. That is the structural cause of the owner's "samey" complaint (every run, junk jog or breakthrough, got the same weight), and it lands the heaviest reading at the worst moment, immediately after a run when the runner's cognitive capacity is lowest and before they have reported RPE, pain, or notes. The north-star (decision 3) reframes the post-activity touchpoint as a two-stage `Exchange`. We adopt it for A4.

**The decision.** A finished activity produces a two-stage exchange. Stage one is a lightweight LLM **opener** that fires immediately: lean context, short output, a genuine human reaction plus tappable RPE/pain prompts, never blocking on input. Stage two is a **fuller turn**, the deep prose coaching, fired on the runner's reply or a timer, whichever comes first. Whether stage two fires at all, and how deep each stage goes, is governed by **`Salience`** (how noteworthy the event is to this relationship): an unremarkable run lets the opener be the entire exchange; a salient one earns a fuller turn. Salience is computed as a **hybrid**: the deterministic pipeline supplies the facts (the existing baseline/flag/adherence signals plus one new **novelty** signal) and a **safety override** (a red-flag flag forces non-silence and forces a fuller turn, the model can never decide to stay quiet on a safety signal), while the opener LLM judges the human calls of depth, tone, and whether-to-deepen. There is no monolithic deterministic salience score.

The exchange is **one evolving `coach_reports` row**, not a new table: the opener writes it in a light state, the fuller turn reads the opener (for continuity, so it advances the conversation rather than restarting) and fills it in, preserving both halves. The two stages are produced by **one prompt in two modes** (`coach_message_v2`, schema 2.0 extended to hold the opener prose alongside the fuller message), keeping the M0 versioned-cache identity `(activity_id, prompt_id, schema_version)` intact and the coach's voice coherent across both stages; cutover and rollback stay a `COACH_PROMPT_ID` config flip. The pipeline splits into an opener job (ingest -> analyze -> opener -> notify -> conditionally schedule stage two via `rq-scheduler`) and an **idempotent** fuller-turn job (guarded by a per-stage sentinel, so a reply-triggered run and the timer-triggered run cannot double-fire); a reply (a `CheckIn` or `CoachChatMessage`) fires the fuller turn early, bounded by an `EXCHANGE_REPLY_WINDOW` so a check-in on an old activity never spins up a fresh exchange. Each stage sends its own notification (per-stage dedup, sentinels on `Activity`). The M4-M10 learning-loop write-back, the `Consolidation` job, and the M5 eval gate all attach to the **fuller turn**; the opener carries none of them.

A4 builds on a **block-of-one** (real `Block` grouping is A1) and defers all **tappable delivery to I1** (the opener already emits the `TappableOption`s, so I1 is pure delivery, no rework).

## Considered options

- **Keep the single-shot report (A3 status quo).** Rejected: it is the named cause of the samey output and dumps depth at the low-cognitive-capacity moment. The reframe exists to kill exactly this.
- **Always fire both stages, let the coach be silent at stage two.** Rejected: spends an LLM call to decide "say nothing" on every junk run and re-introduces the over-treatment that makes the output feel inhuman. Conditional stage two is the faithful implementation of "the opener can be the whole exchange."
- **A deterministic salience score gating depth.** Rejected: it hard-codes a human judgment ("how noteworthy is this to this person right now") into a formula, the over-reliance on derived values the owner flagged. The facts are deterministic; the judgment is the model's.
- **Pure LLM salience with no deterministic safety override.** Rejected: a red-flag run's treatment would then depend on the model not slipping. The safety floor must be deterministic, mirroring the existing referral-nudge pattern.
- **A new `Exchange` table now / two separate prompt ids.** Rejected for A4: it reworks the M0 cache identity A3 built on and pre-empts A1's event-unit data model. The Exchange record stays deferred to A1; A4 rides `coach_reports`.
- **Cancel the scheduled timer job when a reply arrives early.** Rejected: `rq-scheduler` cancellation is racy. A sentinel-guarded idempotent fuller-turn job lets the late timer harmlessly no-op.
- **Edit the opener's Telegram message in place at stage two.** Rejected: an edit fires no new ping (the runner misses it), email cannot edit, and it loses the followed-up, conversational feel. Two separate sends read as a conversation.

## Consequences

- A4 carries a migration (opener-prose storage plus the opener notification sentinel); A3 had none, but A4 legitimately changes the data model.
- `coach_message_v1` stays byte-stable for A3-era cached rows; `coach_message_v2` becomes the active prompt; the prose path's `max_tokens` headroom keeps it immune to the legacy structured-path truncation bug.
- A low-salience run ends at the opener and contributes nothing to the learning loop or the eval. This is correct: there was nothing substantive to learn from or to score.
- Because the opener is pre-input, all durable-memory write-back, `Consolidation`, and the M5 rubric attach to the fuller turn. The opener's safety is still enforced by the policy validator at write time, just not by the offline rubric.
- "One exchange per block" is literally true only once A1 lands, but true by construction now (block-of-one), so nothing unwinds.
- I1 (tappable delivery, in-app then the Telegram inbound webhook) is the next milestone and slots on without A4 rework. Until I1, a Telegram reply means opening the app to use the existing check-in form or chat.
- Future reviews should not re-suggest a single-shot report, an always-fire stage two, or a deterministic salience score: two-stage, conditional, and hybrid-salience are the design, not accidents.
