# The coaching corpus is keyed lexical retrieval over a code-resident house library under partial authority tiering

The north-star reframe (`coach-north-star.md` §3.8) gives the coach a `Coaching corpus`: the retrievable knowledge layer it grounds its *judgment* in (as opposed to its *facts*, which come from the data). The corpus has three intended parts — always-present house principles, a retrievable library of training schools of thought selected by `Coaching stance`, and the runner's own `User materials`. P1.2 builds the substrate for the first two; `User materials` (P4) does not exist yet and stays deferred. ADR 0008 already established that coach memory is a four-layer pull model over a lean working context; this ADR decides how the corpus rides that seam, where it lives, and how its lower authority is enforced so philosophy can never overrule the data or the safety floor.

The forces: the coach's reports are "too samey" and the base prompt is "too conservative, too preoccupied with correctness" (the owner's brain-dump), so the corpus must be able to genuinely reweight how the coach frames training — different schools, visibly different emphasis on the same run. But the project's standing invariant is that nothing lower than measured data overrides measured data or the safety floor (a `Belief` never overrides today's re-derived `DerivedMetric`; the `narrative` is voice-only and never evidence). Philosophy is the newest, and one of the lowest, of these knowledge sources. Letting it in without a precedence rule reopens exactly the "philosophy licenses unsupported advice" hole the `Authority tiering` glossary term exists to close.

**The decision.** The corpus is **keyed lexical retrieval over a small, house-authored, code-resident library**, surfaced as a **context-pack section** (the `narrative` model, not the `voice` model), under a **partial authority tier (safety/data outrank philosophy) enforced in three layers**.

1. **Keyed lexical lookup, no vector DB.** The runner *selects* a school explicitly (via the stance dial, P1.3), so there is nothing to semantically match — retrieval is a pure lookup by school id. Deep-research Q4 confirmed (3-0) that keyword/lexical retrieval reaches RAG-level performance without embeddings, and a vector store would be infrastructure with no query to justify it. The library is small (an always-present house core plus three house-original schools in P1.2: aerobic-base/high-mileage, polarized/quality, enjoyment-and-consistency).

2. **The library lives as code (`corpus.py`), not a table.** It is house-authored, read-only at runtime, type-checked, and diff-reviewable — the same kind of domain data as the voice presets in `voice.py`, and stored the same way. There are no per-user rows and no runtime writes in P1.2, so a table would buy a migration and a seed-reconciliation cost for nothing. `User materials` (P4) is per-user, runtime-ingested, untrusted content with a fundamentally different storage and trust profile; it will get its own store designed against P4's constraints, not this house library retrofitted.

3. **The corpus rides the context pack via the retrieval seam, governed by a prompt rule — it is knowledge the coach reasons over, never instructions it obeys.** `retrieval.py` gains a `fetch_corpus` beside `fetch_prior_digests`; `context.py` builds a `corpus` pack section carrying the always-present house principles plus the keyed school's principles and method-framing; it degrades to house-core-only when no school resolves, exactly as `narrative` degrades to null. This places the corpus on the *data-the-coach-reasons-about* side of the architecture, not the *instructions-the-coach-obeys* side — which is what the glossary's "never let corpus text issue instructions to the coach" constraint demands. The voice model (a system-prompt persona block) was the wrong home precisely because baking the corpus into the system prompt structurally invites instruction-leakage.

4. **Partial authority tiering is enforced in three layers, mirroring how `narrative` was handled.** (a) A new prompt rule: philosophy reweights emphasis and method-framing only, stays goal-tethered, and never licenses unsupported advice or overrides measured data or the safety floor. (b) A new *narrow* deterministic validator rule: corpus-is-not-evidence — reject citing a `corpus.*` field path as report evidence, exactly mirroring the narrative-is-not-evidence rule, and kept deliberately narrow (it matches only corpus path citations) so it never forces a false-positive fallback. (c) A cross-school invariance eval assertion, the regression sensor, parallel to P1.1's `voice_preserved_safety_surface`. The safety floor itself is already code-enforced and school-agnostic (the existing validator rules fire regardless of what steered the output), so the corpus introduces no new safety-floor hole — only a new evidence-laundering risk (closed by the narrow rule) and a new emphasis-drift risk (held by the prompt rule and eval).

5. **P1.2 supplements the base prompt's philosophy; it does not extract it.** The house core adds an explicit coaching-principles layer on top of the existing implicit philosophy in `SYSTEM_PROMPT_MESSAGE_V2`, which is unchanged. Extracting and retuning the "too conservative" base-prompt philosophy is a tone-changing rewrite of the live production prompt with its own regression risk; it is a tracked follow-up, not a rider on the substrate build. The extraction also wants the corpus to exist first, so the dependency order is substrate-then-extraction regardless.

## Considered options

- **Semantic retrieval / a vector DB over the philosophy library.** Rejected: the runner selects the school explicitly, so there is no semantic query to serve; embeddings would be infrastructure justifying itself. Research Q4 shows keyed lexical lookup reaches RAG-level performance without it.
- **Store the corpus in a `coaching_corpus` DB table, seeded by migration.** Rejected for P1.2: no per-user rows and no runtime writes, so a table pays migration and seed-reconciliation cost for zero benefit, and breaks the `voice.py` symmetry. Pre-building it for P4's user materials is speculative — P4's untrusted, per-user, runtime-ingested content wants its own store designed against its own constraints.
- **Inject the corpus as a system-prompt persona block (the voice model), gated by a prompt-id set.** Rejected: it frames the corpus as persona/instructions, structurally inviting the one thing the glossary forbids — corpus text issuing instructions to the coach. The corpus is retrieved knowledge the coach reasons over, the same category as `narrative`, and belongs in the pack under a prompt rule.
- **Split: house core in the system prompt (always present), selected school in the pack (retrieved).** Rejected: two homes for one concept, and the house core would stop being "retrieved," breaking the retrieval-seam framing the whole milestone is built on.
- **Enforce tiering with the prompt rule and eval only; add no validator rule.** Rejected: it leaves the evidence-laundering hole (the corpus cited as fact) that the parallel narrative precedent deliberately closed with a narrow validator rule. Given the standing "the validator gate is not bypassable" stance, the corpus — the same category as narrative — gets the same defense-in-depth.
- **Heavier code-level tiering that strips or flags any corpus-derived claim.** Rejected: semantically infeasible — there is no deterministic way to tell "philosophy-licensed unsupported advice" from legitimate framing — and it would force false-positive fallbacks. That boundary is the prompt rule's and the eval's to hold, not the validator's.
- **Extract and retune the "too conservative" base-prompt philosophy inside P1.2.** Rejected as scope creep: it is a tone-changing rewrite of the live production prompt that would make the substrate PR impossible to review as "did the substrate land correctly?" because the coach's voice changed underneath simultaneously. Filed as a separate follow-up that gets its own before/after eval.

## Consequences

- P1.2 ships a new `corpus.py` (house core + three schools as frozen dataclasses), a `fetch_corpus` in `retrieval.py`, a `corpus` pack section in `context.py`, a new prompt `coach_message_v4 = coach_message_v3 + corpus addendum` (the `Vn = V(n-1) + addendum` idiom; existing versions stay byte-stable), a new narrow validator rule, and a cross-school invariance eval assertion. Activation is a `COACH_PROMPT_ID=coach_message_v4` config flip; rollback to any other id is a config flip with zero code change.
- The corpus is built end-to-end with retrieval keyed to one hardcoded default school (aerobic-base). Runner-facing school *selection* — the stance dial that flips the key — is P1.3, which inherits a verified retrieval seam and adds only the selector.
- Because the corpus rides the pack as a new section, `coach_message_v4` reports legitimately carry a new fact-free `corpus` section and regenerate (the M0 versioned-cache idiom); pre-corpus history is retained.
- A tracked follow-up issue covers extracting and retuning the base-prompt philosophy into the corpus house-core; it is explicitly out of P1.2's scope.
- The authority boundary is stated once here and enforced in three places (prompt rule, narrow validator rule, eval assertion). If a later corpus feature widens what philosophy can touch — or if `User materials` (P4) brings the hardest tier (user materials beat house philosophy) — it must re-open this ADR. `User materials` also introduces an untrusted-input surface this ADR does not, so `aiw-security-testing` applies to P4, not to P1.2 (a house-authored library carries no untrusted input).
