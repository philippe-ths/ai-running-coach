Key

How to read the graph. Each node is a stage in one conversational turn — from the surface the runner opened, through the relationship baseline and the assembled system prompt, to the policy floor and the rows written. Click any node to trace its lineage and open its real artifact on the right.

Node colour — what a node IS
Client surface — something the runner's browser sends or is shown (a launcher, the pointer, a stream frame).
Runner input / decision — runner-declared config, or a tap that authorises a write.
Deterministic code — a builder, resolver, tool, or the assembled prompt. No model involved.
Stored table — a row read or written (Thread, CoachChatMessage, UserProfile, Activity).
Durable memory — the runner memory profile and the cross-thread continuity built from it.
Gate — the kill switch, the spend cap, and the policy floor. Each can stop a turn.
LLM — a model call: the turn itself, and the auxiliary Haiku title writer.
