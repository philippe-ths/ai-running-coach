# P1.2 Corpus Substrate Build Brief

> The what. The why and the load-bearing decisions live in `docs/adr/0014-coaching-corpus-is-keyed-lexical-retrieval-over-a-code-resident-house-library.md` (keyed lexical retrieval over a code-resident house library, pack-section injection, partial authority tiering in three layers, supplement-not-extract), extending `docs/adr/0008-coach-memory-is-a-four-layer-pull-model.md`. The full design context is `docs/vision/p1-voice-and-stance.md` §6-7 (Coaching stance, the P1 re-slice) and the research findings (esp. Q4: keyed lexical lookup reaches RAG-level with no vector DB). The roadmap is `docs/vision/coach-north-star.md` §5. Vocabulary (`Coaching corpus`, `Authority tiering`, `Coaching stance`, `User materials`) is in `CONTEXT.md`. This is milestone 2 of the P1 re-slice (Voice dials → **Corpus substrate** → Stance dials); one concern, one issue, one PR. The schema fields, prompt mechanics, and the choice of default school below are reversible build choices (not ADR-worthy); they are banked defaults open to veto at plan-review.

## Goal

The coach grounds its coaching *judgment* in a retrievable corpus: an always-present house-principles core plus a keyed school of training thought, surfaced as a context-pack section the coach reasons over (never as instructions, never as fact). P1.2 builds the full keyed-lookup retrieval end-to-end, wired to one hardcoded default school (aerobic-base), and proves the partial authority tier — philosophy reweights emphasis and method-framing but never overrides measured data or the safety floor. Runner-facing school *selection* is P1.3; this milestone proves the substrate.

## Deliverables

1. **The corpus library, authored as code** (`app/services/coach/corpus.py`, mirroring `voice.py`): frozen dataclasses, no LLM, no I/O. An always-present **house core** (the compact set of coaching principles loaded every exchange) plus **three house-original schools** (not impersonations of named methodologies): **aerobic-base/high-mileage** (durability, easy volume, the long-game lens — the wired default), **polarized/quality** (threshold + hard-easy structure, the improver lens), **enjoyment-and-consistency** (feel-led, habit-first, the recreational lens). Each school's entry = `id`, `name`, a one-line stance summary, `principles[]` (a few short bullet principles), `method_framing` (how it frames training methods/emphasis), `emphasis_hints` (what to foreground). Short structured fields, not long prose (banked default: keyed lookup over compact entries, per ADR 0014 / research Q4).

2. **The retrieval function** (`app/services/coach/retrieval.py`): a `fetch_corpus(school_id)` beside `fetch_prior_digests` — a pure keyed lookup into `corpus.py` returning the house core plus the named school, degrading to **house-core-only** when no school resolves (the `narrative`-degrades-to-null idiom). No DB read; the corpus is code-resident. The seam is the only place the rest of the system reads the corpus.

3. **The `corpus` context-pack section** (`app/services/coach/context.py`): a `_build_corpus_context` gathered into the pack beside `narrative`/`longitudinal`, carrying the house principles + the keyed school's principles and method-framing. The run's facts (`DerivedMetric`) are untouched — the corpus is judgment knowledge, not grounding. In P1.2 the school key is the hardcoded default (`aerobic-base`); P1.3 replaces the constant with the runner's stance selection. The pack stays byte-stable for non-corpus prompts (the section is emitted only under a corpus-aware prompt id).

4. **Prompt composition** (`app/services/coach/prompts.py`): a new two-stage prompt id **`coach_message_v4`** = `coach_message_v3` + a static corpus addendum, following the `Vn = V(n-1) + addendum` idiom (existing versions stay byte-stable; only `prompt_id` advances). The addendum is the **prompt rule 25**: the `corpus` section is the school of thought you coach from — it reweights *emphasis and method-framing only*, stays tethered to the runner's real goal and the measured data, and **never** licenses advice the data does not support, grounds a factual claim, or overrides this run's re-derived `DerivedMetric` or the safety floor. Composed for **both opener and fuller modes**. A new `CORPUS_PROMPT_IDS = {coach_message_v4}` set gates the pack section and the addendum (the set also implies voice-aware and two-stage, since v4 builds on v3).

5. **The narrow validator rule** (`app/services/coach/validator.py`): a seventh rule, **corpus-is-not-evidence** — reject output that cites a `corpus.*` field path as report evidence, exactly mirroring the narrative-is-not-evidence rule (rule 6). Kept deliberately narrow (it matches only corpus path citations), so it never forces a false-positive fallback. Shared `check_*` body, wired into both `validate_policy` and `validate_message_policy`.

6. **The cross-school invariance eval assertion** (`app/services/coach/eval/rubric.py`): a regression sensor parallel to `voice_preserved_safety_surface` — one fixed activity carrying a safety flag, run through all three schools, asserting the surfaced safety flags and the `validate_message_policy` outcome are **identical across all schools**. School changes emphasis, never the floor or the facts.

7. **Activation + config**: the corpus era arrives by setting `COACH_PROMPT_ID=coach_message_v4`; rollback to `coach_message_v3` (or any other id) is a pure config flip with zero code change. v4 reports regenerate (new prompt id legitimately carries the new `corpus` pack section); pre-corpus history retained (the M0 versioned-cache idiom).

## Acceptance criteria

- AC1: Under a non-corpus prompt (`coach_message_v3` and earlier), the context pack and coach output are byte-identical to today — the `corpus` section is emitted only under a corpus-aware prompt id, and `corpus.py` / the new validator rule are inert.
- AC2: Under `coach_message_v4`, the pack carries a `corpus` section with the house core + the keyed default school (aerobic-base); the run's `DerivedMetric` / facts in the pack are unchanged.
- AC3: **Floor + fact invariance across schools** — the same flagged activity run through all three schools produces identical surfaced safety flags and an identical `validate_message_policy` outcome; only emphasis/framing differs. (The ADR 0014 partial-tier gate.)
- AC4: Swapping the keyed school visibly changes the coaching emphasis/method-framing on the same run (the substrate differentiates), while AC3 holds — proving the corpus is load-bearing, not dormant.
- AC5: With no school resolvable, `fetch_corpus` degrades to house-core-only and the exchange still generates (the `narrative`-degrades-to-null idiom); nothing breaks.
- AC6: The corpus-is-not-evidence validator rule rejects a report that cites a `corpus.*` path as evidence, and does **not** fire on legitimate emphasis/framing that draws on the corpus without citing it as fact (narrow by construction; no false-positive fallback).
- AC7: Flipping `COACH_PROMPT_ID` back to `coach_message_v3` serves the prior path with zero code change; `coach_message_v1`..`v3` stay byte-stable.

## Verification

TDD throughout; `make backend-test` green at every step. Unit tests for: `corpus.py` lookup (house core always present, each school resolves, unknown id → house-core-only); `fetch_corpus` degradation; `_build_corpus_context` pack-section shape (present under v4, absent otherwise, facts untouched); `build_system_prompt` corpus composition in both opener and fuller modes (existing versions byte-stable, addendum present under v4); the corpus-is-not-evidence validator rule (fires on a `corpus.*` evidence citation, silent on legitimate framing). The **cross-school invariance test (AC3)** is the load-bearing gate and runs against a fixed flagged fixture. The eval self-test (`make eval-selftest`) covers the new rubric assertion against good/bad fixtures. End-to-end on `make seed-local` data: generate a report under `coach_message_v4`, confirm the corpus framing lands, swap the default school and confirm emphasis shifts while the floor holds. `aiw-security-testing` is **not** in scope — the corpus is house-authored, read-only, with no untrusted-input surface (that arrives with `User materials` in P4). Quality of the coaching framing under each school is an owner judgement (subjective tone), surfaced for the owner, not asserted by the AI.

## Out of scope

Runner-facing school selection and the stance emphasis axes (Data↔Sentiment, Process↔Outcome) — that is P1.3; this milestone hardcodes the default school. `User materials` ingestion and the hardest authority tier (user materials beat house philosophy) — P4, which needs the untrusted-input store that does not exist yet. Extracting/retuning the "too conservative" base-prompt philosophy into the house core — a tracked follow-up issue with its own before/after eval (ADR 0014 §5); P1.2 supplements, it does not extract. Any DB table or migration (the corpus is code-resident). Any change to the context pack's facts / `DerivedMetric`, the safety floor, or the existing six validator rules. Authoring more than three schools (the strength-led + periodization schools are an additive follow-up when P1.3's selection surfaces them).
