Full design context is `docs/vision/p1-voice-and-stance.md` §6-7 (Coaching stance, the two resolved emphasis axes, the P1 re-slice) and research Q3 (explicit axis-named steering beats implicit) / Q4 (keyed lookup, no vector DB). This is milestone 3 of the P1 re-slice (Voice dials → Corpus substrate → **Stance dials**); one concern, one issue, one PR. ## Goal

The runner controls the coach's `Coaching stance`: which school of training thought the coach reasons from (selected from the `Coaching corpus`, replacing P1.2's hardcoded default) and where it sets two emphasis axes — Data ↔ Sentiment and Process ↔ Outcome. Stance is runner-sovereign (declared and re-declared by the runner, never secretly inferred — the voice precedent) and goal-tethered (it reweights emphasis and method-framing only, never the facts or the safety floor — the corpus authority tier). This makes the P1.2 corpus substrate user-controllable and completes the P1 re-slice.

## Deliverables

1. **The stance domain module** (`app/services/coach/stance.py`, mirroring `voice.py`): frozen dataclasses, no LLM, no I/O. The two emphasis `DialAxis`-style axes with pole labels (Data 1 ↔ Sentiment 5; Process 1 ↔ Outcome 5), the moderate `DEFAULT_EMPHASIS` (3/3 balanced), the resolved `StanceProfile` (selected `school_id` + the two effective 1-5 axis values + `is_default`), and `resolve_stance(relationship) -> StanceProfile` (precedence: stored value wins, else the default; an undeclared stance resolves to `school_id=DEFAULT_SCHOOL_ID` aerobic-base + balanced 3/3, preserving the P1.2 default experience). `_clamp` reused/mirrored from voice. This module never renders prompt text (that is `prompts.py`).

2. **Two additional house schools** (`app/services/coach/corpus.py`): author **strength-led** ("cardio serves the lifting" — the strength athlete's lens) and **periodization** (structured base→build→peak phasing) in the established `School` shape (`id`/`name`/`stance`/`principles[]`/`method_framing`/`emphasis_hints[]`), house-original (not impersonations), distinct in emphasis from the existing three. Five schools total. **School prose is owner-taste** — flagged prominently in the PR for owner judgement; the cross-school invariance gate guarantees they cannot breach the floor regardless of prose.

3. **Storage** (`app/models/coaching_relationship.py` + a zero-backfill migration off `e1f2a3b4c5d6`): three new nullable columns — `stance_school` (String, a `SCHOOLS` key), `stance_data_sentiment` (SmallInteger 1-5), `stance_process_outcome` (SmallInteger 1-5). Null resolves to the default at read time (the voice nullable+default+zero-backfill idiom); pre-stance behaviour unchanged until a runner declares a stance.

4. **Read-time resolution** (`app/services/coach/service.py`): a `_resolve_stance_for_activity(db, activity) -> StanceProfile` mirroring `_resolve_voice_for_activity`, threaded into all **three** `build_context_pack` call sites (`get_or_generate_coach_report`, `generate_opener`, `generate_fuller`).

5. **School threading + the new `stance` pack section** (`app/services/coach/context.py`): `build_context_pack` gains a `stance` (StanceProfile) parameter; the runner's `stance.school_id` is passed into `_build_corpus_context(prompt_id, school_id=...)` (replacing the hardcoded `DEFAULT_SCHOOL_ID`); a new `_build_stance_context(prompt_id, stance)` builds a `stance` pack section carrying the two axis values + pole labels, emitted **only** under a stance-aware prompt id (the `block`/`corpus` Optional-and-drop idiom, so the pack stays byte-stable elsewhere). The `corpus` section keeps its P1.2 shape (now varying by selected school); the run's `DerivedMetric` / facts are untouched — stance is judgment/preference, never grounding.

6. **Prompt composition** (`app/services/coach/prompts.py`): a new two-stage prompt id **`coach_message_v5`** = `coach_message_v4` + a static emphasis addendum (the `Vn = V(n-1) + addendum` idiom; existing versions byte-stable). The addendum is **prompt rule 26**: the `stance` section carries the runner's two emphasis axes — honour them by reweighting *what you foreground and lead with* (numbers vs felt experience; habits/execution vs results/goals), while everything in GROUNDING and SAFETY stays invariant; the axes change emphasis only, never the facts, the safety floor, or the runner's real goal. Composed for **both opener and fuller modes**. A new `STANCE_PROMPT_IDS = {coach_message_v5}` set gates the `stance` pack section and the addendum; `CORPUS_PROMPT_IDS` gains `coach_message_v5` (v5 is corpus-aware, since it builds on v4), as do `TWO_STAGE_PROMPT_IDS` and `VOICE_PROMPT_IDS`. School selection needs no new rule (v4's rule 25 already consumes the `corpus` section).

7. **API + schema** (`app/api/coach.py`, `app/schemas/stance.py`): `GET`/`PUT /api/coach/stance` mirroring the voice endpoints — read returns the runner's current selection plus a catalog (the five schools' id/name/stance + the two axes' pole labels + the balanced default) the UI renders from; write is the **only** writer of stance state (runner-sovereign, no background job mutates it). Validated: `stance_school` must be a known `SCHOOLS` key or null; axes clamped 1-5.

8. **Frontend stance panel** (`frontend/components/`, `frontend/app/profile/page.tsx`, `frontend/lib/types/stance.ts`): a stance declaration panel on `/profile` mirroring `VoiceDialsPanel` — a school picker (five options, each with its one-line stance), two emphasis sliders (Data↔Sentiment, Process↔Outcome) with pole labels, and a small mirror visualization. Reads/writes `/api/coach/stance`. **UX/quality is owner judgement** — surfaced, not asserted.

9. **Activation + config**: the stance era arrives by setting `COACH_PROMPT_ID=coach_message_v5`; rollback to any other id is a pure config flip with zero code change. The **repo config default stays `coach_report_v10`**. Per the owner's ratified Decision 5, P1.3 includes performing the prod flip as part of the milestone: the slow/worst-case generation path is verified before the flip (the P1.1 activation lesson), the exact Railway var change + rollback line are prepared, and the **flip itself is owner-authorized and owner-executed** (or run with an explicit per-action go); the live path is confirmed after.

## Acceptance criteria

- AC1: Under a non-stance prompt (`coach_message_v4` and earlier), the context pack and coach output are byte-identical to today — the `stance` section is emitted only under a stance-aware prompt id, and `stance.py` / the new prompt rule are inert. (Critically: under `coach_message_v4` the corpus still resolves to the hardcoded default school, so P1.2 stays byte-stable.)
- AC2: Under `coach_message_v5`, the pack carries a `stance` section with the two emphasis axes, and the `corpus` section carries the runner's **selected** school (not the hardcoded default); the run's `DerivedMetric` / facts are unchanged.
- AC3: **Floor + fact invariance across stances** — the same flagged activity run across every school and across the emphasis-axis extremes produces identical surfaced safety flags and an identical `validate_message_policy` outcome; only emphasis/framing differs. (The ADR 0014/0015 authority-tier gate; the load-bearing test, extending `test_corpus_invariance.py` to vary by the stored stance.)
- AC4: Changing the selected school visibly changes the coaching emphasis/method-framing on the same run, AND moving an emphasis axis visibly shifts what the coach foregrounds (Data↔Sentiment, Process↔Outcome), while AC3 holds — proving stance is load-bearing, not dormant.
- AC5: An undeclared stance resolves to the P1.2 default (aerobic-base + balanced 3/3) and generates a report byte-stable against the P1.2-wired default under the matching prompt; a null/unknown school degrades to house-core-only via the existing `fetch_corpus` seam without breaking the exchange.
- AC6: `GET`/`PUT /api/coach/stance` round-trips a selection (school + two axes); an unknown school or out-of-band axis value is rejected; no background job ever writes stance state.
- AC7: Flipping `COACH_PROMPT_ID` off `coach_message_v5` serves the prior path with zero code change; `coach_message_v1`..`v4` and the `coach_report_v*` chain stay byte-stable.

## Verification

TDD throughout; `make backend-test` green at every step (baseline to confirm first: handoff cites 1099 passed, 4 deselected). Unit tests for: `stance.py` resolution (default when undeclared, stored value precedence, clamp, school passthrough); the two new schools resolve via `fetch_corpus`; `_build_corpus_context` honours a threaded `school_id`; `_build_stance_context` pack-section shape (present under v5, absent otherwise, facts untouched); `build_system_prompt` v5 composition in both opener and fuller modes (existing versions byte-stable, rule 26 present under v5); the stance API round-trip + validation. The **cross-stance invariance test (AC3)** is the load-bearing gate — extend `test_corpus_invariance.py` to sweep all five schools × emphasis extremes against a fixed flagged fixture, asserting identical floor + facts. `make eval-selftest` green (ten assertions; the cross-school `corpus_preserved_safety_surface` sensor already covers the floor — confirm it still passes under v5; a stance-specific emphasis-drift sensor needs the deferred #164 judge and is out of scope). Frontend: `npm run test` (lint + build) + `npm run smoke`. **Pre-flip slow-path verification (the P1.1 activation lesson, load-bearing because P1.3 activates in prod):** `make seed-local` → set `COACH_PROMPT_ID=coach_message_v5` locally → generate the two-stage opener→fuller across a couple of schools/emphasis settings, confirming cache regen, display-safe read, and that emphasis visibly shifts — a single ~$0.20 paid LLM run, owner-flagged, run only with explicit go. `aiw-security-testing` is **out of scope** — stance is selection + clamped dials, no untrusted input (free-form philosophy is `User materials`, P4). Coaching-tone/UX quality under each stance is an owner judgement, surfaced not asserted.

## Out of scope

`User materials` ingestion and any stance free-text hatch (P4 — runner-supplied coaching content is an untrusted-input store with the hardest authority tier, deferred by ADR 0014/0015). The hardest authority tier (user materials beat house philosophy) — P4. The deferred #164 semantic-judge / corpus-emphasis-drift sensor (the deterministic eval guards the safety floor across stances, not philosophy over-steering). Extracting/retuning the "too conservative" base-prompt philosophy into the house core (#266, its own before/after eval). Any change to the run's facts / `DerivedMetric`, the safety floor, or the existing seven validator rules (stance adds no validator rule — the emphasis axes are runner dials, not citable text, so they open no new evidence-laundering path). Onboarding flow beyond the profile panel. The deprecated `Activity.opener_notification_sent_at`/`coach_notification_sent_at` column delete (separate approved task).
