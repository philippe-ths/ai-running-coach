## Dual-Track Exchange: one call, prose surface plus strict tool-call analytical tail

### Summary

One Anthropic Messages call on Opus 4.8 with adaptive thinking produces two coupled artifacts in generation order: the coach's full prose message (text blocks, markdown, the product the runner sees everywhere) followed by a single strict-schema tool call `record_coach_analysis` carrying the analytical record (headline, evidence-backed claims, machine-readable next_steps, risks, questions with tappable options). The prose is the only rendered surface; the tail is the exchange digest written at generation time (ADR 0008's processed-artifact layer) and the sole input the M4-M10 learning loop and M5 eval read structurally. The deterministic policy validator runs unweakened over the union of prose and tail text plus the tail's structured claims, with the existing retry-then-record flow. The two tracks are atomic: a missing or invalid tail after one corrective retry makes the whole exchange a fallback, so machine-readability of commitments is never silently lost. Legacy v1-v8/1.2 reports stay byte-stable and cached; the new shape ships as prompt_id `coach_exchange_v1`, SCHEMA_VERSION 2.0, a clean cache miss under the existing versioned-cache seam.

### Output Contract

LLM call (in `llm.py`, new method `generate_exchange`): `client.messages.create(model=settings.COACH_MODEL_ID (claude-opus-4-8), max_tokens=4096, thinking={"type":"adaptive"}, output_config={"effort":"high"}, system=<frozen v_exchange prompt + playbook>, tools=[RECORD_COACH_ANALYSIS_TOOL], tool_choice={"type":"auto"}, messages=[{"role":"user","content":json.dumps(pack_dict)}])`. Note: the current `temperature=0.2` in llm.py must be removed (400 on Opus 4.8); keep the existing 60s timeout and transient-retry logic. Response shape consumed by a new `app/services/coach/output_contract.py::parse_exchange_response`: thinking block (display omitted, not stored), text block(s) concatenated = `message` (markdown prose, 150-400 words, coach voice), exactly one `tool_use` block whose `input` validates as `CoachAnalysisRecord`. The tool is defined `strict: true` with a pinned, hand-frozen JSON schema (not regenerated from Pydantic at runtime, so the prompt-cache prefix stays byte-stable): {headline: str (required, short verdict), claims: 1-6 of {text, evidence:[{field,value}]} ranked strongest first (claims[0] is the lead argument), next_steps: 0-3 of {action, details, why, theme_hint: enum[easy_discipline|add_quality|add_long_run|other], evidence}, risks: 0+ of {flag, explanation, mitigation}, questions: 0-4 of {question, reason, options: 0-4 short tappable strings}, additionalProperties false}. Stored (coach_reports row): new nullable TEXT column `message` = prose; existing `report` JSON column = CoachAnalysisRecord dump; `meta` (confidence, model_id, prompt_id=coach_exchange_v1, schema_version=2.0, input_hash, policy_violations) unchanged in shape; `context_pack` and `raw_llm_response` (serialized text+tool_use) as today. Rendered: frontend `CoachReportPanel` shows `message` via react-markdown plus a meta footer and question-option chips from `analysis.questions[].options`; Telegram/email templates render title (activity Headline + distance + confidence, unchanged) and the prose body, dropping the field-by-field bullet rendering (inline-keyboard taps are I1 scope, the contract already carries options). API: `CoachReportRead` gains optional `message: str|null` and `analysis: CoachAnalysisRecord|null`; legacy rows return the old `report` shape with `message` null, and the frontend branches on `message` presence.

### Prompt Strategy

v1-v8 stay byte-stable in PROMPT_VERSIONS exactly as committed (cached-report reproducibility and the eval's cross-version compare depend on it). `coach_exchange_v1` is a fresh prompt, not an additive concatenation, because the v1 base's "Output ONLY valid JSON" and inline JSON schema are incompatible with prose-first; it carries forward every discipline from rules 2-22 rewritten for prose (grounding/no invention, evidence-strength routing, zone language, interval confidence gating, discount signals, M4 advance-not-restate, M6 RPE weighting, M7 advise-not-nag, M8 hedge-by-tags-never-override, M9 calibrated correction + non-diagnostic referral, M10 preference framing, #168 load-vs-intensity), then the new output contract: "Reason privately first. Then write your message to the runner: markdown, your voice, lead with the verdict, concrete numbers, no JSON, no headings echoing a form. Then call record_coach_analysis exactly once: every commitment, claim, risk, and question in your message must appear in the record, and the record must contain nothing your message did not say." ACTIVITY_PLAYBOOKS append as today via `build_system_prompt`. Reason-before-structure mechanics on the API: adaptive thinking (`thinking={"type":"adaptive"}`, the only mode on Opus 4.8; budget_tokens and temperature would 400) puts genuine extended reasoning before any visible output; within the visible output, text blocks precede the tool_use block in the same response, so token-generation order is thinking -> prose -> structured tail in one call, with the prose unconstrained (no constrained decoding on the product, which is the exact "forcing structure early hurts the response" concern this reframe exists to fix) and only the thin tail schema-constrained via strict tool use. `output_config={"effort":"high"}`. Prompt-cache hygiene: tools render before system, so the pinned tool JSON plus frozen system prompt form a stable cacheable prefix; the volatile pack stays in the user message.

### Validator Strategy

The five rules move to a new entry point `validate_exchange_policy(message: str, record: CoachAnalysisRecord, pack)` in validator.py, sharing the exact same compiled regexes and rule bodies as today via an internal refactor into rule functions that take (policed_text, structured_view); the legacy `validate_policy(content, pack)` entry point is kept byte-equivalent because rubric.py assertion 3 reuses it for scoring retained v1-v8 reports. Policed text = `message` concatenated with every text field of the tail (claims, next_steps action/details/why, risks, questions), so the surface the gate scans strictly grows: the prose the user actually reads is now policed directly, which strengthens rules 2 (uncalibrated zones), 4 (ungated interval claims), and 5 (medical scope) rather than weakening anything. Rules 1 (questions required on null check-in) and 3 (risk flag must exist in the flags array) keep reading the structured tail (`record.questions`, `record.risks[].flag`), unchanged. Flow parity with today: violations trigger the single `_retry_with_fixes` re-prompt; residual violations are recorded in `meta.policy_violations` and the row stored, identical to current semantics, so the floor is not bypassed or loosened. One flagged (optional, owner decision) hardening: because prose is now the product, persisting `medical_overreach` after retry could be promoted to force `is_fallback=True` instead of store-with-flag; this is a strengthening, never required for parity. Known blind spot, documented not hidden: deterministic code cannot verify that every commitment in prose is mirrored in the tail (free-text divergence); the prompt makes mirroring a hard rule and the tail remains the authoritative machine record, mirroring the M5 "deterministic floor with documented blind spots" discipline.

### Learning Loop Strategy

Commitments stay machine-readable because the tail's `next_steps` keeps the exact field names (`action`, `details`, `why`) the loop reads today. M7: `adherence.py` is pure and takes `prior_next_steps: List[dict]`, so it is unchanged; only `_build_adherence_context` in context.py gains a shape branch (schema_version 2.x reads `report["next_steps"]` from the record, legacy reads as today). The new `theme_hint` enum is stored for audit/debug only and is NOT consumed by the M7 keyword classifier in v1, preserving constraint 3 (an LLM-supplied label never enters the deterministic write path; promoting it to a recall extension behind the negation guard is a separately evaluated follow-up). M4: `_prior_report_digests` maps headline from `record.headline`, lead_argument from `record.claims[0].text`, next_steps from `record.next_steps`, branching by row schema_version; the digest contract into the pack (`longitudinal.prior_reports`) is unchanged, so prompts and rubric assertion 4 see the same shape. M8: `write_back_beliefs` reads only discount_signals from the pack and M7 outcomes, both deterministic, untouched; fallback exchanges still skip write-back. M10: `build_preference_profile` reads accumulated adherence beliefs, untouched; the eval's `framed_for_adherence` classifies `record.next_steps` via the existing M7 `_classify`. Per ADR 0008 the tail doubles as the stored exchange digest (headline, lead claim, commitments), written at generation time so A2 retrieval is cheap, and per Authority tiering nothing in it ever overrides the run's re-derived DerivedMetric.

### Eval Gate Strategy

rubric.py is refactored so each assertion takes a normalized `(message, record, pack)` triple; harness.py gains a shape adapter in its row loader: schema 2.x rows load `message` + CoachAnalysisRecord directly, legacy rows adapt CoachReportContent (message="", claims=lead_argument+key_takeaways) and score through the retained legacy text extractor, so historical scorecards remain reproducible. Per assertion: (1) led_with_headline reads `record.headline` (unchanged semantics). (2) discounted_inflated_hr scans the policed text (prose+tail) with the same confound/discount keyword floors, including the #176 non-elevated-drift NOT_APPLICABLE branch. (3) no_medical_overreach reuses the production gate verbatim (new entry point for new rows, legacy entry point for old rows), keeping eval and runtime sharing one definition. (4) advanced_not_parroted compares `record.claims[0].text` + next_steps words against the prior digest with the same Jaccard threshold; digests carry identical content across shapes so cross-version comparison stays apples-to-apples. (5) abstained_on_thin_trend and (7) load_not_framed_as_intensity scan assertive prose, where "assertive" is approximated deterministically by excluding sentences ending in "?" (using the existing `_SENTENCE_SPLIT_RE`), plus tail claims/next_steps/risks; this is a documented heuristic shift from the old structured questions-exclusion. (6) framed_for_adherence classifies `record.next_steps` via M7 `_classify`, unchanged. Scorecards remain scoped to (prompt_id, schema_version), so `coach_exchange_v1`/2.0 gets a fresh scorecard and the harness's regression compare against `coach_report_v8`/1.2 still gates the cutover. fixtures.py gains dual-track good/bad synthetic fixtures (including a prose-only-no-tail bad case and a tail-trend-claim bad case) so `make eval-selftest` validates both shapes without a DB or key.

### Schema And Storage Changes

DB: one additive alembic migration on `coach_reports`: nullable `message` TEXT column. No other table changes; A3 deliberately does not introduce Exchange/Block tables (A1/A2 own those). The `report` JSON column is reused: legacy rows hold CoachReportContent, 2.0 rows hold CoachAnalysisRecord, discriminated by the existing `schema_version` column. Constants: SCHEMA_VERSION "1.2" -> "2.0" in service.py; COACH_PROMPT_ID default -> "coach_exchange_v1" in config. Cache key implications: identity stays (activity_id, prompt_id, schema_version) with the existing unique constraint; the version bump is a clean cache miss, `get_active_report_row` ignores old rows, regeneration retains all v1-v8 history (the M0 seam), `force=true` replaces only the active 2.0 row, and the IntegrityError concurrent-winner path is unchanged. `input_hash` remains the pack fingerprint. Pydantic (app/schemas/coach.py): add `CoachClaim`, `CoachAnalysisRecord` (reusing CoachNextStep with added optional `theme_hint`, CoachRisk, CoachQuestion with added optional `options: List[str]` max 4); keep CoachReportContent and its legacy coercions untouched for old rows; `CoachReportRead` gains optional `message` and `analysis`. New module `app/services/coach/output_contract.py` holds the frozen tool-definition JSON, `parse_exchange_response`, and `extract_policed_text`. Frontend `lib/types/coach.ts` adds `CoachAnalysisRecord`/`CoachClaim` and optional `message` on `CoachReport`. PROMPT_VERSIONS gains the `coach_exchange_v1` entry so `_to_read`'s debug system_prompt lookup keeps working.

### Fallback Semantics

is_fallback means exactly what it means today, extended to the dual-track invariant: "no validated machine record exists for this exchange." Triggers: anthropic transport error after the client's retries; empty prose (no text block); zero or multiple tool_use blocks; tool input failing CoachAnalysisRecord validation. For the structural cases the service makes one corrective retry (re-issues the call with an appended instruction naming the defect, e.g. "You wrote a message but did not call record_coach_analysis; produce both"); if the retry still fails, the exchange is a fallback. On fallback: store a templated message ("Analysis is temporarily unavailable for this activity. Your metrics are recorded on the activity page.") plus a minimal templated record (headline "Analysis unavailable", one claim, one review-your-metrics next_step), is_fallback=True, no belief write-back (existing guard), and M4/M7 skip it (they already filter non-fallback rows). The tracks are atomic by design: LLM prose is never delivered without a schema-valid tail (the validator's structured rules and the learning loop would be blind to it), and a tail is never stored without the prose the runner actually saw (adherence must never judge the runner against advice they were never shown). Persistent policy violations after the policy retry keep today's semantics (stored with meta.policy_violations populated, not fallback), with the optional medical_overreach hardening noted under validator strategy.

### Migration Path

Indefinite coexistence by versioned cache, no destructive migration. Step order: (1) ship schema migration (nullable `message`), new Pydantic models, output_contract module, validator refactor with both entry points, rubric/harness shape adapters, fixtures, all behind the still-default v8 prompt; run `make eval-selftest` and the full backend suite. (2) ship the generation path (llm.generate_exchange minus temperature, service.py dual-track flow, coach_exchange_v1 prompt) and flip COACH_PROMPT_ID; from that moment every coach-report request and pipeline run is a clean cache miss that generates 2.0 rows while v1-v8 rows are retained untouched. (3) frontend: CoachReportPanel branches on `message` presence, rendering markdown prose + question-option chips for 2.0 rows and the existing field panel for legacy rows (old activities keep rendering without regeneration); types updated in lib/types/coach.ts. (4) notifications: telegram_template/email_template branch the same way (new rows render title + prose body + activity URL; legacy renderer kept); `Notified at` dedup is untouched so no re-notification. (5) chat: `chat.py`'s report-context builder reads `message` for 2.0 rows, legacy fields otherwise. context.py digest/adherence gatherers branch by schema_version permanently, since old rows persist. Cutover gate: run `make eval` to produce the coach_exchange_v1/2.0 scorecard over real regenerated reports and regression-compare against the v8/1.2 scorecard before calling A3 done. Rollback is one config flip back to coach_report_v8 (v8 rows still cached, legacy code paths intact). Single-user MVP means no coordination window; preview deployments share prod DB, so the schema migration is additive-only by requirement.

### Risks

(1) Tail omission or malformation: the model writes prose but skips or fumbles the tool call; mitigated by the hard prompt rule, strict schema, one corrective retry, and atomic fallback, but fallback rate must be monitored across cutover (it is the headline health metric for A3). (2) Prose/tail divergence: a commitment phrased in prose but absent from next_steps silently exits the M7 loop, or a tail entry the prose never said makes adherence judge invisible advice; not deterministically checkable, bounded by the mirroring rule, M7's conservative abstentions, and eval spot-checks; this is the design's principal accepted blind spot. (3) Validator surface growth: full prose through rules 2/4/5 regexes raises false-positive retries (e.g. "depression" in elevation prose is already guarded, but volume rises); watch meta.policy_violations rates. (4) Opus 4.8 API prerequisites: temperature must come out of llm.py or every call 400s; verify COACH_MODEL_ID in prod config before flip. (5) Eval heuristic weakening on assertions 5/7: question exclusion by "?"-sentence is coarser than the old structured questions field; documented, and the tail's structured questions field partially compensates. (6) Cost/latency: prose+tail at effort high is larger than today's 1024-token JSON (estimate 2-3x output tokens per report; trivial in absolute terms for a single-user MVP on Opus pricing, but worth logging usage). (7) Dual-shape rendering bugs in frontend/Telegram during coexistence; covered by branching on `message` and keeping legacy renderers byte-stable. (8) Assertion 4 still cannot catch a semantic parrot in prose; unchanged blind spot, LLM-judge upgrade remains future work.

### Tradeoffs

Versus a structured-output-only shape (output_config.format with the prose as a JSON string field): that guarantees parseability but runs the entire product through constrained decoding and cannot guarantee prose-before-structure token order, recreating the "structure first hurts the response" failure the owner identified; the tool-tail keeps the prose genuinely unconstrained at the cost of a structural-failure mode (handled by retry+fallback). Versus two calls (write prose, then a second extraction call to build the record): two calls decouple the tracks and could never lose the prose to a tail failure, but double cost/latency, let the record drift from what the author meant (extraction errors become learning-loop corruption), and break the one-call decision 4 explicitly took. Versus keeping the structured report and rendering it as prose client-side: preserves per-claim traceability but is exactly the samey, form-shaped output the reframe exists to kill. What this design gives up: per-sentence machine traceability of the rendered surface (evidence refs live in the tail, not pinned to prose sentences), the old field-level rendering affordances (risk cards, takeaway bullets) in favour of one message, deterministic certainty that prose and record agree, and some eval precision on question exclusion. What it deliberately defers: Exchange/Block tables and the two-stage cadence (A1/A4), retrieval-based working context (A2), tappable-option delivery on Telegram (I1), and any use of theme_hint in the deterministic write path. The bet, matching the north-star ADR candidate: trade per-claim traceability of the surface for humanity and reasoning quality, while the analytical record keeps the safety floor, the eval gate, and the learning loop fully structured.

## Message-First Clean Break: the Exchange record with a strict-tool tail

### Summary

The post-activity coach output becomes an Exchange: one Anthropic call on claude-opus-4-8 with adaptive thinking produces private reasoning, then a prose message (the product), then a single strict-schema tool call carrying a thin machine tail (headline, commitments, tappable options, optional citations, declared flags). A new `exchanges` table becomes the record; the structured CoachReport schema is frozen at v8/1.2 and retired for new generations while all cached rows stay readable. The deterministic policy validator is re-targeted to scan the full prose surface plus the tail with the same five rules (medical scope strengthened to force a fallback on persistent violation), and the M5 eval scores both shapes through one ScoredOutput adapter so the quality gate never goes dark across the cutover. The M4-M10 learning loop survives because `tail.commitments[*].action/details` keeps the exact text contract the M7 keyword classifier and M4 digest already consume, and belief/adherence write-back stays untouched and deterministic.

### Output Contract

LLM produces, in one `messages.create` call: (1) adaptive thinking blocks (not stored verbatim; `meta.thinking_present` recorded), (2) text blocks concatenated in order = `message` (markdown prose, the product, target 150-400 words, coach-decided), (3) exactly one `tool_use` block for tool `record_exchange_tail` (strict: true, input_schema from `ExchangeTail.model_json_schema()`). New `backend/app/schemas/exchange.py`: `TAIL_SCHEMA_VERSION = "2.0"`; `Commitment {action, details, why, evidence: list[EvidenceRef]}` (deliberately identical text shape to today's CoachNextStep so M7's `_classify` works unchanged); `TappableOption {id, label, kind: rpe|pain|reply|dispute|custom, payload: dict}` (the successor of `questions`, per north-star I1); `Citation {claim, field, value}` (optional, context-pack paths); `ExchangeTail {headline: str (<=80 chars, the memory hook), commitments: 0-3, options: 0-4, citations: list, flags_referenced: list[str]}`. Stored on the `Exchange` row: `message` TEXT, `tail` JSON (validated), `meta` JSON (model_id, prompt_id, schema_version, input_hash=pack.fingerprint(), confidence, generated_at, policy_violations, tail_degraded, stop_reason), `context_pack` JSON (kept verbatim for the eval, as today), `raw_llm_response` TEXT (serialized content blocks for audit), `is_fallback`. Frontend (`frontend/components/CoachMessagePanel.tsx`, types in `frontend/lib/types/exchange.ts`) renders `message` through the existing react-markdown pipeline, `options` as tappable buttons (A3: post into coach chat / prefill check-in; A4 wires the two-stage flow), `commitments` as a small chip list; no structured panels. Telegram (`render_exchange_telegram`): title = `tail.headline` + distance + confidence, body = message converted md-to-plaintext with deterministic paragraph-boundary truncation under the 4096-char limit plus the activity URL; email template mirrors it. The tail carries affordances and memory hooks only; the prompt forbids tail content not present in the message.

### Prompt Strategy

Byte-stability is preserved by namespace, not mutation: `coach_report_v1`..`coach_report_v8` constants remain byte-identical in PROMPT_VERSIONS (cached reports keep resolving their system_prompt for the debug view), and a new family starts at `COACH_EXCHANGE_V1` ("coach_exchange_v1"), versioned additively exactly like today once shipped. coach_exchange_v1 rewrites the JSON-schema instructions into message discipline while carrying every substantive rule forward (evidence-strength routing, zone language, confidence gating rule 13, discount signals, M4 advance-not-restate, M6 RPE weighting, M7 advise-not-nag, M8 hedge-by-tags-never-override, M9 calibration+referral, M10 preference framing, rule 22 load-vs-intensity, and the Authority tiering line that today's measured data beats every belief and narrative), plus: write one coherent message to the runner, reason privately first, end by calling record_exchange_tail exactly once, the tail may only restate what the message says, declare any pipeline flag you discuss in flags_referenced. ACTIVITY_PLAYBOOKS append via build_system_prompt unchanged. Reason-before-structure mechanics, concretely: `llm.py` gains generate_exchange using `client.messages.stream(model="claude-opus-4-8", thinking={"type": "adaptive"}, output_config={"effort": "high"}, system=[{...,"cache_control": {"type": "ephemeral"}}], tools=[record_exchange_tail with strict: true], tool_choice={"type": "auto"}, max_tokens=4000)` then get_final_message(); the existing `temperature=0.2` MUST be removed (400 on Opus 4.8). tool_choice stays auto deliberately: forcing the tool suppresses the preceding prose and couples badly with thinking, so ordering thinking -> text -> tool_use is achieved by adaptive thinking plus a prompt mandate, with a deterministic one-shot retry if the tool call is missing. The parser is order-agnostic (concatenate text blocks, take the single named tool_use anywhere) so a model that emits the tail before a closing sentence still parses. Strict tool use guarantees the tail input matches the JSON schema; Pydantic re-validates on our side. We never send a tool_result; stop_reason "tool_use" is the expected terminal state.

### Validator Strategy

`validator.py` gains `validate_exchange(message: str, tail: ExchangeTail, pack) -> list[PolicyViolation]`; the five rules' pattern internals are extracted into shared scan functions reused verbatim by the legacy `validate_policy` (so cached-report behavior is byte-identical and the eval keeps one shared definition). Scanned surface = message + tail.headline + every commitment field + option labels + citation claims, so prose IS governed. Rule mapping: (1) missing_questions_for_null_checkin becomes missing_input_request_for_null_checkin: all check_in fields null requires len(tail.options) >= 1 or a question sentence in the message; (2) uncalibrated_zone_reference: same Z[1-5] regex over the full surface, unchanged; (3) invalid_risk_flag becomes unwarranted_flag_reference, two deterministic checks: every tail.flags_referenced must be in pack.metrics.flags (the prompt requires declaring any pipeline flag the message discusses), plus a prose scan for canonical flag identifiers and a small per-flag phrase map (maintained beside flags.py) naming flags not in the pack; (4) ungated_interval_claim: identical regexes, already text-based; (5) medical_overreach: identical four-pattern gate, already text-based, this is the safety floor and prose is its natural domain. Retry semantics as today (one corrective re-prompt with fix_instructions), with one strengthening: a medical_overreach that survives the retry forces is_fallback=True instead of being stored with the violation recorded, because the message is now rendered verbatim with no structured field selection to hide behind. All other persistent violations are recorded in meta.policy_violations and stored, parity with today. The gate runs on every generation including retries and is never skippable; rule 3 is the one rule whose recall profile genuinely changes (prose paraphrase of a non-fired risk is harder to see than a structured field), which is named as a risk, covered by the declared-list contract plus an eval counter, and never used as a reason to drop the check.

### Learning Loop Strategy

One load-bearing contract keeps the loop alive: `tail.commitments[*].action/details` is the machine-readable successor of `next_steps[*].action/details`, same free text classified deterministically. M7 (`adherence.py`): pure logic untouched; the gather in `context.py` reads the most recent prior non-fallback exchange's `tail["commitments"]` instead of `report["next_steps"]`; `_classify`, negation guards, comparability and opportunity gates, and the disputed pushback scan work unchanged because the field shape is identical. M8 (`beliefs.py` + `belief_store.py`): completely untouched; `write_back_beliefs(db, activity, pack)` derives deltas only from pack signals (discount_signals, M7 outcomes), stays off the LLM, and is called after each non-fallback exchange store at the same seam. M10 (`preference.py`): untouched, reads M8 beliefs. M4 longitudinal: `_prior_report_digests` becomes `_prior_exchange_digests`; PriorReportDigest fields populate from tail.headline, the deterministic first sentence of the message as lead_argument, and commitments as next_steps strings, keeping the token bound. During coexistence the digest gather unions exchanges and legacy coach_reports ordered by date (a deterministic adapter maps legacy report fields to the digest), so advance-not-restate spans the cutover seamlessly. The eval harness reads commitments through the same adapter. Degraded tails (model skipped the tool call after retry) carry commitments=[], so the loop abstains rather than guessing, which is the existing M7 abstention discipline.

### Eval Gate Strategy

`eval/rubric.py` gets a `ScoredOutput` adapter (new `eval/surface.py`): {message_text, assertive_text, headline, commitments, options}, buildable from a legacy CoachReportContent (existing extractors) or an Exchange row (message + tail), so all seven assertions stay shape-agnostic and one rubric gates both worlds. Re-mapping: (1) led_with_headline reads tail.headline; (2) discounted_inflated_hr runs its confound/discount keyword scan over message+tail (the #176 NOT_APPLICABLE branch unchanged); (3) no_medical_overreach keeps reusing the production rule 5 verbatim via the shared scan functions; (4) advanced_not_parroted computes Jaccard between current headline+commitments and the prior exchange digest, same threshold, re-baselined; (5) abstained_on_thin_trend keeps its question carve-out via deterministic sentence split excluding sentences ending in "?" from assertive_text; (6) framed_for_adherence classifies commitments with the same M7 `_classify`; (7) load_not_framed_as_intensity is already a sentence-level prose scan. `harness.py` loads Exchange rows for the active (prompt_id, schema_version) and still loads CoachReport rows when given a legacy pair, so `make eval` compares the coach_exchange_v1 scorecard against the frozen coach_report_v8 baseline at the assertion level; a new scorecard column counts tail_degraded so a tail-skipping model regression is visible. `fixtures.py` gains synthetic good/bad exchanges and `make eval-selftest` validates both shapes with no DB or key. Gating procedure before the default flips: seed local from prod, generate exchanges for the seeded activities, run the scorecard, require no assertion-level regression vs the v8 baseline and re-tune the parrot threshold on flowing prose; documented in docs/testing/coach-report-eval.md.

### Schema And Storage Changes

One alembic migration adds `exchanges`: id UUID PK, user_id FK, activity_id FK, kind (A3: "activity_analysis"; A4 adds "opener"/"chat_reply"), prompt_id, schema_version, message TEXT, tail JSON, meta JSON, context_pack JSON, raw_llm_response TEXT, is_fallback bool default false, created_at; unique constraint (activity_id, kind, prompt_id, schema_version), the direct successor of the M0 versioned cache key so a future prompt/tail bump regenerates while retaining history. `coach_reports` is untouched: no column changes, no row migration, SCHEMA_VERSION frozen at "1.2", rows readable forever via the existing read path. TAIL_SCHEMA_VERSION starts at "2.0" to signal the clean break. New ORM model `backend/app/models/exchange.py` added to the barrel; new service `backend/app/services/coach/exchange_service.py` owning get_or_generate_exchange with the same IntegrityError concurrency-yield as today. Cache-key implication: config COACH_PROMPT_ID default flips to `coach_exchange_v1`; the exchange path keys on (activity_id, "activity_analysis", COACH_PROMPT_ID, TAIL_SCHEMA_VERSION); the legacy report cache becomes read-only (lookups by stored prompt_id, no new inserts). input_hash stays pack.fingerprint() in meta for eval reproducibility. CoachingContext and RunnerBaseline are untouched.

### Fallback Semantics

is_fallback=True on an Exchange means the prose message is not real coaching: set when (a) anthropic.APIError/transport failure after the existing retry policy, (b) the response contains no text block, or (c) medical_overreach persists after the policy retry (new, stricter than today). Fallback content is fully deterministic: a templated message ("I could not put together a proper read of this run; your metrics are recorded on the activity page.") plus a tail whose headline comes from the deterministic classifier `compose_headline` (no LLM), commitments=[], options=[]. Fallback exchanges are excluded from belief write-back, from the M4 digest and M7 gather (non-fallback filters as today), and from the eval scorecard (skipped_fallback counter). Distinct from fallback is the degraded-tail state: a real message whose record_exchange_tail call is missing or fails Pydantic validation even after one corrective retry; the exchange stores the real message with is_fallback=False, tail={headline: compose_headline(...), commitments: [], options: []}, meta.tail_degraded=true. The runner still gets the coaching, the learning loop abstains for that exchange, eval assertion 1 plus the tail_degraded scorecard column make the failure visible rather than silent. Parse failure of the message itself cannot occur in the new shape (prose needs no parsing), which removes today's largest fallback trigger (json.JSONDecodeError/ValidationError on the whole report).

### Migration Path

Single PR sequence on one branch, single-user blast radius. Step 1: schema + models + ExchangeTail + exchange_service + validator validate_exchange + coach_exchange_v1 + llm.generate_exchange, all behind the existing COACH_PROMPT_ID config (exchange path activates only for coach_exchange_* ids). Step 2: eval adapter + fixtures + selftest; run the offline gate on a seeded local DB and compare to the v8 baseline before any default flips. Step 3: API endpoint GET /api/activities/{id}/exchange (generate/force semantics mirroring today), frontend CoachMessagePanel + types, notification branch in build_coach_notification with render_exchange_telegram/email; chat.py grounds its system prompt on exchange.message instead of the report JSON. Step 4: flip COACH_PROMPT_ID default to coach_exchange_v1; process_new_activity's coach step calls get_or_generate_exchange; Activity.coach_notification_sent_at dedup unchanged. Coexistence rules: the /coach-report endpoint becomes read-only cached (404 if no cached row, generation rejected), CoachReportPanel remains mounted only when a legacy report exists and no exchange does, and the M4/M7 gathers union exchanges with legacy reports via the digest adapter until each user has enough exchanges, after which legacy rows naturally fall out of the recency window. Old cached reports are never regenerated, deleted, or reshaped, satisfying the versioned-cache retention constraint. An ADR (docs/adr/0009-coach-output-is-a-prose-exchange.md, the north-star section 7 candidate) records the trade of per-claim machine traceability for message quality; project-context.md and CONTEXT.md reconciliation (Notification/CoachReport entries) land in the same PR per the maintenance checklist.

### Risks

(1) Validator rule 3 recall drops on prose: a paraphrased non-fired risk is harder to catch than a structured risks[].flag; mitigated by the declared flags_referenced contract, the per-flag phrase map, and an eval counter, but it is a real surface change on a safety-adjacent rule. (2) The model may skip or malform the record_exchange_tail call; if frequent, commitments starve the M7/M8 loop; mitigated by strict tool schema, one corrective retry, the tail_degraded scorecard column, and headline fallback from the deterministic classifier. (3) Eval lexical heuristics (parrot Jaccard 0.5, trend terms, discount terms) were tuned on terse list fields and will behave differently on flowing prose; thresholds must be re-baselined on seeded real data before the default flips or the gate gives false signal. (4) llm.py currently sends temperature=0.2, which 400s on claude-opus-4-8; the migration must strip sampling params or every exchange falls back. (5) Telegram 4096-char limit forces deterministic truncation of a now free-form message; a bad truncation can cut mid-advice (paragraph-boundary truncation plus the activity URL mitigates). (6) Coexistence digest adapter bugs could silently break advance-not-restate across the cutover; covered by fixture tests spanning a legacy-report-then-exchange sequence. (7) Cost/latency rise: Opus 4.8 with adaptive thinking at effort high versus today's 1024-token call; acceptable for a single user but worth a meta token-usage log. (8) The chat grounding change is small but touches the only other LLM surface; regression-test the chat path.

### Tradeoffs

Chosen deliberately per the north-star: humanity and reasoning quality over per-claim machine traceability. Given up versus keeping the structured schema: (a) mandatory evidence arrays per claim become optional tail citations, so the audit trail thins from every-claim to strongest-claims; (b) the frontend loses ready-made structured panels (takeaways, risks, questions) and bets the whole surface on prose quality; (c) validator rule 3 and parts of the eval move from exact structured fields to text heuristics, a weaker floor on those specific surfaces; (d) two record types live in the DB forever (consistent with the existing versioned-cache philosophy, but more code paths than an in-place schema extension); (e) migration cost is materially higher than the cheap alternative (adding an optional message field to CoachReportContent and keeping the JSON contract), which was rejected because it keeps structure-first generation, the exact failure mode the owner's research flagged, and keeps the report rather than the Exchange as the protagonist. Kept at full strength, not traded: the deterministic policy gate (strengthened on medical), the deterministic belief/adherence write-back, the machine-readable commitments contract, byte-stable prompt history, the versioned cache, and authority tiering.

## In-Place Reframe: same row, same loop, the report JSON learns to carry a message

### Summary

The coach's output becomes prose without leaving the `coach_reports` table, the `report` JSON column, or the existing service/eval plumbing. One Anthropic Messages call with adaptive thinking produces, in token order: private reasoning, the coach's prose `message` (markdown text blocks, the product), then exactly one strict-schema tool call `record_coach_tail` carrying the thin tail — `headline` (the memory hook), 0-3 `next_steps` with the exact `action`/`details`/`why` field names the M4/M7 loop already consumes, `risks` (flag declarations for validator rule 3), and `questions` with tappable `options`. Message and tail are merged into one `CoachMessageReport` dict and stored in the existing `report` JSON column under a new `(prompt_id="coach_message_v1", schema_version="2.0")` cache identity — **zero alembic migrations, zero new tables, zero new columns** (constraint 7 satisfied vacuously, which matters on a preview-shared production DB). Because the tail's `next_steps` live at the same JSON key with the same field shape as today, `retrieval.fetch_prior_commitments` and the entire `adherence.py` module run **verbatim, unmodified** — the A2d seam was built for exactly this. The validator's six rules police the prose plus the tail through the same shared rule bodies; the M5 rubric scores both shapes through a two-line branch in its text extractors so the gate never goes dark. The design is deliberately model-agnostic: the new LLM method sends no sampling parameters and uses `thinking={"type":"adaptive"}`, both of which are valid on the current prod `claude-sonnet-4-6` and on `claude-opus-4-8`, so the open model fork stays a pure `COACH_MODEL_ID` config decision with no code consequences. This is not client-side prose rendering of a structured report: the message is generated first, unconstrained, as the primary artifact; the tail is generated after it and forbidden from carrying content the message did not say.

### Output Contract

**LLM call** (`llm.py`, new method `generate_message_with_tail`): `client.messages.create(model=self.model, max_tokens=4000, thinking={"type": "adaptive"}, system=system, tools=[RECORD_COACH_TAIL_TOOL], tool_choice={"type": "auto"}, messages=[{"role": "user", "content": user}], timeout=_TIMEOUT_SECONDS)`, retaining the existing transient-retry loop (timeout/connection/5xx, one retry, 1s backoff) unchanged. No `temperature`, `top_p`, or `top_k` is sent: adaptive thinking is the supported mode on both Sonnet 4.6 and Opus 4.8, sampling parameters 400 on Opus 4.8, and omitting them is valid everywhere — so flipping `COACH_MODEL_ID` later requires no code change (the existing `generate_json`/`stream_chat` with `temperature=0.2` are kept byte-stable for the legacy path and chat). `RECORD_COACH_TAIL_TOOL` is a hand-frozen JSON definition (not regenerated from Pydantic at runtime, keeping the prompt-cache prefix byte-stable; tools render before system, so frozen tool + frozen system prompt form the cacheable prefix and the volatile pack stays in the user message) with `strict: true` and `additionalProperties: false`:

- `headline`: string, required, <=80 chars — the verdict label and digest memory hook.
- `next_steps`: 0-3 of `{action, details, why, evidence: [{field, value}]}` — byte-compatible with today's `CoachNextStep`. Zero allowed: a light exchange may legitimately commit to nothing, and M7 abstains on empty rather than judging invisible advice.
- `risks`: 0+ of `{flag, explanation, mitigation}` — the structured declaration validator rule 3 checks against `pack.metrics.flags`, exactly as today.
- `questions`: 0-4 of `{question, reason, options: 0-4 short strings}` — `options` is the one new field (decision 4's tappable affordances; rendered as chips now, wired to the two-stage flow in A4/I1).

Notably absent from the tail: `thesis`, `lead_argument`, `key_takeaways`, and any claims array. The vision says structure carries affordances and memory hooks, never content — the prose carries the argument, and putting a parallel claims record in the tail would re-create the form the milestone exists to kill and invite prose/tail divergence. (This is a deliberate departure from the Dual-Track candidate's `claims` array; the cost — per-claim evidence refs — is accounted under Tradeoffs.)

**Parsing** (`output_contract.py`, new ~80-line module): concatenate all text blocks in order = `message` (markdown, target 120-350 words, coach-decided); take the single `record_coach_tail` tool_use anywhere in the content (order-agnostic, so a trailing sentence after the call still parses); validate tool input as `CoachTailContent` (Pydantic re-validation over the strict-schema guarantee). Thinking blocks are not stored.

**Storage**: `CoachMessageReport` = `{message, headline, next_steps, risks, questions}` dumped into the **existing** `report` JSON column, discriminated by the row's existing `schema_version` column ("2.0"). `meta` keeps its shape plus a new optional `tail_degraded: bool`. `context_pack`, `raw_llm_response` (serialized text + tool_use blocks), `digest`, `is_fallback` as today.

**Rendered**: `CoachReportPanel` branches on `report.message` presence — 2.0 rows render the message through `react-markdown` (already a dependency, already used for report text) with the headline as title, question `options` as tappable chips that prefill the existing `CoachChat` input, and the meta footer; legacy rows keep the current field panel untouched, so old activities render forever without regeneration. `render_coach_report_telegram`/email branch the same way: title stays `headline + distance + confidence` (unchanged contract), body becomes the message as plaintext with paragraph-boundary truncation under Telegram's 4096-char limit, dropping the field-by-field bullets. `CoachReportRead.report` becomes a discriminated union (`CoachReportContent | CoachMessageReport`); `frontend/lib/types/coach.ts` adds the message shape. `chat.py` needs **zero changes**: it interpolates `json.dumps(report)` into its system prompt, and the 2.0 dict (message included) serializes straight in.

### Prompt Strategy

`coach_report_v1`..`coach_report_v10` stay byte-identical in `PROMPT_VERSIONS` (cached-report debug reproducibility and the eval's cross-version compare depend on it). The new prompt is `COACH_MESSAGE_V1` (`"coach_message_v1"`), registered in the same `PROMPT_VERSIONS` dict so `_to_read`'s debug lookup and `build_system_prompt` + `ACTIVITY_PLAYBOOKS` work unchanged (the playbooks reference metrics fields, not output fields, so they append as-is). It is a fresh prompt, not a concatenation: v1's "Output ONLY valid JSON" base and inline JSON schema are structurally incompatible with prose-first, so every substantive discipline from rules 2-24 is carried forward rewritten for a message — grounding/no-invention, evidence-strength routing per claim, zone language (rule 10), training context, confidence gating (rule 13), honesty-over-polish, discount signals (rule 15), M4 advance-not-restate, M6 RPE weighting, M7 advise-not-nag, M8 hedge-by-tags-never-override, M9 calibrated correction + non-diagnostic referral, M10 preference framing, #168 load-vs-intensity, #171 coach-the-available-data, A2c narrative-is-voice-only — followed by the new output discipline:

> Reason privately first. Then write your message to the runner: markdown prose in your own voice, lead with the verdict, concrete numbers from the data, no JSON, no headings that echo a form, no bullet-list-of-everything — say what matters and stop. Then call `record_coach_tail` exactly once. The tail is bookkeeping, not a second report: its headline names the verdict your message led with, its next_steps are exactly the commitments your message made (none if it made none), its risks declare exactly the pipeline flags your message discussed, its questions are the questions your message asked, with short tappable answer options. The tail must contain nothing your message did not say.

Reason-before-structure is delivered mechanically, not just rhetorically: adaptive thinking puts genuine private reasoning before any visible output; within the visible output, the prose text blocks precede the tool_use block under `tool_choice: auto` plus the prompt mandate, so token generation order is thinking → message → tail in one call, with the product itself never under constrained decoding (the exact "forcing structure early hurts the response" failure the owner flagged) and only the thin tail schema-constrained via strict tool use. A model that emits the tail early is handled by the order-agnostic parser; a model that skips it is handled by one corrective retry (Fallback Semantics). The questions-belong-in-the-tail rule doubles as the mitigation for the eval's question carve-out (Eval Gate Strategy).

### Validator Strategy

The gate is never bypassed and its surface strictly grows. Internal refactor in `validator.py`: the six rule bodies extract into private functions taking `(policed_text, questions, risks, evidence_fields, pack)`; the existing `validate_policy(content, pack)` entry point is reassembled from them **byte-equivalently** (the eval's assertion 3 reuses it verbatim for retained v1-v10 rows, and the legacy generation path still calls it). A new entry point `validate_message_policy(report: CoachMessageReport, pack)` feeds the same rule bodies:

- **Policed text** = `message` + `headline` + every text field of `next_steps`, `risks`, `questions` — the prose the runner actually reads is now policed directly, which strengthens rule 2 (uncalibrated `Z[1-5]` references), rule 4 (`_INTERVAL_CLAIM_PATTERNS` under low detection confidence), and rule 5 (the full medical-scope battery: dose, diagnosis verbs, med directives, asserted/speculative condition claims with the negation window) rather than weakening anything.
- **Rule 1** (questions required on null check-in) reads `report.questions` — unchanged semantics, structured as today.
- **Rule 3** (risk cites a flag not in `pack.metrics.flags`) reads `report.risks[].flag` — the exact deterministic check, unchanged, because the tail deliberately keeps the structured risks declaration. (This avoids the Message-First candidate's recall drop on rule 3; the prose-paraphrase blind spot exists but the prompt requires any discussed flag to be declared in `risks`, keeping the structural check primary.)
- **Rule 6** (narrative cited as evidence) reads the tail's `next_steps[].evidence` field paths via the existing `_NARRATIVE_FIELD_PATTERN`. Documented narrowing: prose sentences carry no per-claim evidence arrays, so rule 6's machine-checkable surface shrinks to the tail; prompt rule 24's voice-only discipline still governs the prose, and the rule stays deliberately narrow to avoid false-positive fallbacks, per its design comment.

**Flow**: violations trigger the single `_retry_with_fixes` re-prompt (same one-retry-never-loop discipline, retry parsed through the same message+tail contract); residual violations are recorded in `meta.policy_violations` and the row stored — parity with today — with **one strengthening**: a `medical_overreach` that survives the retry forces `is_fallback=True` instead of store-with-flag. Rationale: the message is now rendered verbatim with no structured field selection between the model and the runner, and on a single-user MVP the cost of a rare extra fallback is trivial against shipping prose medical overreach. This is stricter than today, never looser, and is the only behavioural change to the gate.

### Learning Loop Strategy

The evolution angle's strongest property: the loop's machine-readable contract is preserved at the storage layer, so most of the loop is untouched code, not adapted code.

- **M7 / A2d (adherence, commitments)**: `fetch_prior_commitments` in `retrieval.py` reads `report.report.get("next_steps")` and filters to dicts; a 2.0 row stores its tail's `next_steps` at exactly that key with exactly the `action`/`details`/`why` (+ optional `evidence`) fields. **Zero changes** to `retrieval.py`, `adherence.py`, the `_classify` keyword themes, the negation/caution guard, the comparability and opportunity gates, or the disputed-pushback scan. Constraint 1 is satisfied by construction rather than by adapter.
- **M4 (longitudinal digest)**: `digest.build_report_digest` gains one branch — when the report dict carries `message`, `lead_argument` projects from the message's first sentence (split with the rubric's `_SENTENCE_SPLIT_RE`, deterministic); `headline` and `next_steps` project exactly as today. `retrieval._resolve_digest`, `fetch_prior_digests`, `fetch_recent_user_digests`, the `PriorReportDigest` contract into the pack, and the write-time storage in `service.py` are unchanged, so stored and recomputed digests stay byte-equal and the longitudinal section spans the cutover seamlessly (a v10 prior digest and a 2.0 prior digest are the same shape).
- **M8 (beliefs)**: `belief_store.write_back_beliefs(db, activity, pack)` derives deltas only from the pack's `discount_signals` and the M7 outcomes' structured labels — it never reads the report body, which is precisely what `tests/test_writeback_is_llm_free.py` pins. **Untouched**; the test keeps passing without modification, and constraint 6 holds because nothing new enters the write path (the prose, like the report body before it, is simply never read by the write-back).
- **M10 (preference)**: reads accumulated M8 beliefs. Untouched. The pack's `preference_profile` section and prompt discipline carry into `coach_message_v1`'s rule set.
- **A2c (narrative consolidation)**: `consolidate_narrative_job` consumes `fetch_recent_user_digests`, which works via the digest branch. The enqueue point in `service.py` after a non-fallback store is unchanged. Validator rule 6 + prompt rule 24 keep the authority boundary (constraint 8).
- **Authority tiering**: nothing in the tail or message ever mutates a `DerivedMetric`; the tail is the stored exchange record exactly as `CoachReport.report` is today, prior context never override.

### Eval Gate Strategy

The gate never goes dark because the rubric's eight assertion bodies do not change — only the two shared text extractors and the lead extractor learn the new shape, plus a loader branch in the harness.

- `rubric._report_text` / `_assertive_text` / `_lead_text` accept the union: for a `CoachMessageReport`, `_report_text` = message + all tail text (mirroring the production policed surface); `_assertive_text` = message with `?`-terminated sentences stripped via the existing `_SENTENCE_SPLIT_RE` + headline + next_steps + risks (preserving the "a question is not an assertion" carve-out for assertions 5 and 7 — a documented heuristic shift from the structured-questions exclusion, mitigated by the prompt rule that questions live in the tail); `_lead_text` = headline + first paragraph of the message (the #171 "don't headline the caveat" check applies to what actually leads the rendered message).
- Assertion mapping, otherwise unchanged: (1) reads `headline` (now required, so this tightens); (2) confound/discount keyword scan over `_report_text`, including the #176 non-elevated-drift NOT_APPLICABLE branch, untouched; (3) calls `validate_message_policy` for 2.0 rows and the byte-stable `validate_policy` for legacy rows — eval and runtime keep sharing one medical-scope definition; (4) `_forward_words` reads first-sentence-of-message + next_steps for 2.0 rows, and the prior digest carries the same projection, so the Jaccard compare stays apples-to-apples across the cutover (threshold re-baselined on seeded data, since flowing prose distributes words differently than terse fields); (5) and (7) run on the new `_assertive_text`; (6) classifies `next_steps` via the M7 `_classify`, untouched; (8) uses the new `_lead_text`.
- `harness.score_db_reports` branches its row parse on `row.schema_version`: "2.0" validates `CoachMessageReport`, else `CoachReportContent`; everything else (scorecard, micro-average, `compare_scorecards` regression rules including the disappeared-assertion and zero-applicable guards) is unchanged. The active default `(prompt_id, schema_version)` resolves from the prompt family (see Schema And Storage Changes), so `make eval` scores the new shape automatically after the flip.
- `fixtures.py` gains a message-shaped known-good and deliberately-bad pair (bad: no headline, prose trend claim on an abstaining bucket, lap-button advice on recorded laps, load-as-intensity sentence, medical assertion, parroted prior); `run_self_test` validates **both** shapes, so `make eval-selftest` (no DB, no key) gates the refactor before any generation code ships.
- **Cutover gate**: before flipping the default — run `make eval` on the seeded local DB to freeze the `coach_report_v10`/1.2 baseline scorecard; flip locally; regenerate reports for the seeded activities; run `make eval` for `coach_message_v1`/2.0; require no assertion-level regression via `compare_scorecards` and re-tune the parrot threshold on prose. Procedure documented in `docs/testing/coach-report-eval.md`. Constraint 5 holds with no dark period: at every commit, `make eval-selftest` passes and `make eval` can score whichever version is active.

### Schema And Storage Changes

**Database: none.** No alembic migration, no new table, no new column. The `report` JSON column holds `CoachReportContent` dicts for legacy rows and `CoachMessageReport` dicts for 2.0 rows, discriminated by the existing `schema_version` column; `meta` JSON absorbs `tail_degraded`; `raw_llm_response` TEXT absorbs the serialized block list; the A2a `digest` column works unchanged. On a production DB shared with preview deployments this is the lowest-risk storage posture available: old code reading a 2.0 row sees an unfamiliar dict shape only through code paths that already tolerate it (the eval records a parse error; `get_active_report_row` on old code filters to 1.2 and never loads 2.0 rows at all).

**Constants/config**: `service.py` replaces the single `SCHEMA_VERSION = "1.2"` with a family map — `{"coach_report": "1.2", "coach_message": "2.0"}` — and `active_schema_version()` derived from `settings.COACH_PROMPT_ID`'s prefix. `get_active_report_row`, the store path, and the harness default all read it. This makes the cutover (and rollback) a **single config flip with zero code edits**: `COACH_PROMPT_ID=coach_message_v1` activates the 2.0 path; flipping back to `coach_report_v10` re-activates the 1.2 path against its still-cached rows. Cache identity stays `(activity_id, prompt_id, schema_version)` with the existing unique constraint: the flip is a clean cache miss, regeneration retains all v1-v10 history (constraint 4), `force=true` replaces only the active-version row, and the IntegrityError concurrent-winner yield is unchanged. `input_hash` remains `pack.fingerprint()`.

**Pydantic** (`app/schemas/coach.py`): add `CoachQuestionV2(CoachQuestion)` with `options: List[str] = []` (max 4) and `CoachMessageReport` (`message: str` min_length 1, `headline: str`, `next_steps: List[CoachNextStep]` 0-3, `risks: List[CoachRisk]`, `questions: List[CoachQuestionV2]` 0-4). `CoachReportContent` and its legacy coercions untouched. `CoachReportRead.report` becomes the discriminated union. New module `app/services/coach/output_contract.py` holds the frozen tool JSON, `parse_message_response`, and the merge into `CoachMessageReport`. Frontend `lib/types/coach.ts` adds the message shape; `lib/types.ts` barrel re-exports.

### Fallback Semantics

Two distinct degraded states, deliberately separated so the runner's experience and the loop's inputs degrade independently:

- **`is_fallback=True`** keeps today's meaning — no real coaching message exists. Triggers: `anthropic.APIError` after the client's transport retries; a response with no text block (no prose was produced); and, new, a `medical_overreach` violation that survives the policy retry (the strengthening from Validator Strategy). Fallback content is fully templated as today ("Analysis is temporarily unavailable...") in the 2.0 shape, with `headline` from the pack's already-computed deterministic `compose_headline` value (the pack carries it at `activity.headline`), empty next_steps/risks/questions. Fallbacks skip digest storage, belief write-back, consolidation enqueue, M4/M7 reads, and the eval — all existing guards, unchanged.
- **`meta.tail_degraded=True`** (new, not fallback): the model wrote a real message but the `record_coach_tail` call is missing or fails validation even after one corrective retry (the retry re-issues the call with an appended instruction naming the defect: "You wrote your message but did not call record_coach_tail; produce both, the tail restating only what the message says"). The real message is stored and rendered — the runner keeps the coaching — with `headline` backfilled from the pack's deterministic headline and `next_steps=[]`, so M7 abstains for that exchange (the existing abstention discipline: never judge the runner against commitments that were never machine-recorded) and M4's digest carries headline + first sentence only. `tail_degraded` is surfaced as a scorecard counter so a tail-skipping model regression is visible at the gate, not silent.

This deliberately rejects the Dual-Track candidate's atomicity (a tail failure there discards a good message): under the evolution angle the message is the product and the tail is bookkeeping, so losing the bookkeeping for one exchange is an abstention, not a reason to withhold coaching. The one place atomicity is kept is the inverse direction: a tail is never stored without its message (no-text-block → fallback), so adherence can never judge advice the runner never saw. Today's largest fallback trigger — `json.JSONDecodeError` on the whole report — disappears, since the product needs no parsing.

### Risks

1. **Tail omission/malformation rate**: the model may skip or fumble the tool call; mitigated by strict schema, the hard prompt rule, one corrective retry, and the degraded-tail path; `tail_degraded` count is the headline health metric across cutover. A persistently high rate starves M7/M8 of commitments — visible in the scorecard counter before it silently degrades the relationship.
2. **Prose/tail divergence**: a commitment phrased only in prose exits the loop; a tail entry the prose never made would make adherence judge invisible advice. Not deterministically checkable; bounded by the "tail restates only what the message says" rule, M7's conservative abstentions, and eval spot-checks. The slim tail (no claims array) reduces the divergence surface relative to a dual-record design but cannot eliminate it. Principal accepted blind spot.
3. **Validator false positives on prose**: full flowing prose through rules 2/4/5 regexes raises retry volume (e.g. elevation-"depression" is guarded, but prose narrates more); watch `meta.policy_violations` rates post-flip, and note the medical strengthening converts a persistent rule-5 false positive into a fallback rather than a stored flag — precision of rule 5 matters more now.
4. **Sonnet-4.6 prose quality**: the candidate works on the current model, but the "samey, not particularly useful" complaint that motivated the reframe may partly be a model-capability issue; if the eval passes but the prose still reads flat, the fix is the (open) model fork, not this architecture — worth saying explicitly so a flat first week is diagnosed correctly.
5. **Eval heuristic drift on prose**: parrot Jaccard, trend terms, and discount terms were tuned on terse fields; thresholds must be re-baselined on seeded data in step 4 or the gate gives false signal. The question carve-out moves from a structured field to a `?`-sentence heuristic — coarser, documented.
6. **Union read-schema bugs**: `CoachReportRead.report` as a discriminated union is the one API-shape change; a mis-discriminated row breaks the activity page. Covered by serialization round-trip tests for both shapes and the frontend branch on `message` presence.
7. **Adaptive thinking cost/latency**: thinking + 4000 max_tokens versus today's 1024-token JSON call; trivial in absolute terms for one user on Sonnet pricing, but log `usage` in meta for the record.
8. **Rule 6 surface narrowing**: narrative-as-evidence is only machine-checkable in the tail's evidence refs; a prose sentence that leans on the narrative as fact passes the deterministic gate and is caught only by prompt discipline and eval review. Same exposure as both other candidates; named, not hidden.

### Tradeoffs

**Chosen**: the smallest implementation that genuinely inverts generation order. The bet is that decision 4's value lives in three properties — unconstrained prose generated before structure, the validator governing that prose, the frontend rendering it — and not in new tables, new record types, or a renamed artifact. Keeping the `coach_reports` row as the exchange record means the M0 cache, the A2a digest column, the A2b/A2d retrieval seam, and the M7 commitments read all keep working with between zero and one-branch changes, which is the cheapest possible insurance for constraints 1, 4, and 5.

**Given up, versus the clean-break `exchanges` table**: the record keeps a name (`CoachReport`) the vision has demoted, and A1/A2's eventual Exchange/Block model will still need a real record type later — this design defers that cost rather than paying it now, accepting that A3's storage may be re-homed in A1. Given up, versus Dual-Track's claims array: per-claim machine traceability of the rendered surface — evidence refs survive only on next_steps, so the audit trail thins from every-claim to commitments-only, and rubric assertion 4's forward-words read first-sentence prose rather than a structured lead claim. Given up generally: the field-level rendering affordances (takeaway bullets, risk cards) in favour of one message; deterministic certainty that prose and tail agree; some eval precision on the question carve-out.

**Explicitly rejected**: rendering the structured report as prose client-side (structure-first generation — the named failure mode); a delimiter-split two-part text output (no schema guarantee on the tail, brittle parsing, saves nothing over strict tool use); two calls (prose then extraction — doubles cost, lets the record drift from authorial intent, breaks the one-call decision); and deciding the model here (the design is deliberately portable across the open Sonnet/Opus fork so that decision stays with the owner).

**Deferred, not lost**: Exchange/Block tables and naming (A1), retrieval-driven working-context changes (A2 already shipped its half), two-stage cadence and coach-decided depth (A4), tappable-option delivery on Telegram inline keyboards (I1), and any LLM-judge upgrade to the eval's lexical heuristics. Kept at full strength: the six-rule deterministic gate (strengthened on medical), the LLM-free belief write-back with its pinning test untouched, machine-readable commitments at the same storage key, byte-stable prompt history, the versioned cache, and the narrative authority boundary.
